Get Stricture running in your TypeScript project in minutes.

## Prerequisites

Before installing Stricture, ensure your project has:

- **Node.js** 18.x or later
- **TypeScript** 4.5 or later
- **ESLint** 8.x or 9.x (flat config supported)
- A TypeScript project with `tsconfig.json`

:::note
Stricture works with both ESLint legacy config (`.eslintrc.*`) and the new flat config (`eslint.config.js`).
:::

## Choose Your Path

Stricture supports two workflows:

### 🎯 Using Presets (Recommended for most projects)

**Best for:**
- Teams wanting proven architecture patterns
- Projects starting with hexagonal, layered, clean, or modular architecture
- Quick setup with minimal configuration

**Install a preset:**
```bash
npm install -D @stricture/eslint-plugin @stricture/hexagonal
```

**Popular presets:**
- `@stricture/hexagonal` - Ports & Adapters
- `@stricture/layered` - Traditional N-tier
- `@stricture/clean` - Uncle Bob's Clean Architecture
- `@stricture/nextjs` - Next.js App Router patterns

[Explore all presets →](/presets/)

### 🔧 Creating Custom Architecture

**Best for:**
- Unique architecture patterns
- Custom organizational standards
- Creating reusable presets for your company

**Setup:**
1. Install core packages: `npm install -D @stricture/eslint-plugin`
2. Define custom boundaries and rules in `.stricture/config.json`

[Learn to create custom presets →](/guides/custom-presets/)

## Recommended: CLI Setup

The fastest way to get started is with the interactive CLI:

```bash
npx stricture init
```

The CLI will:
- ✅ Detect your project framework (Next.js, NestJS, etc.)
- ✅ Recommend appropriate presets
- ✅ Create `.stricture/config.json` automatically
- ✅ Update your ESLint configuration
- ✅ Install required dependencies

[View full CLI documentation →](/api/cli/)

:::tip[Quick and Easy]
The CLI handles all setup automatically. Skip to [Step 4](#verify-installation) after running `npx stricture init`.
:::

## Manual Setup

Prefer manual control? Follow these steps:

### Install Packages

Install the ESLint plugin and your chosen preset:

```bash
npm install -D @stricture/eslint-plugin @stricture/hexagonal
# or
pnpm add -D @stricture/eslint-plugin @stricture/hexagonal
# or
yarn add -D @stricture/eslint-plugin @stricture/hexagonal
```

> **Note**: `@stricture/core` is automatically installed as a dependency and does not need to be added explicitly.

### Other Presets

Choose the preset that matches your architecture:

#### Hexagonal (Ports & Adapters)

```bash
npm install -D @stricture/hexagonal
# or
pnpm add -D @stricture/hexagonal
# or
yarn add -D @stricture/hexagonal
```

#### Layered Architecture

```bash
npm install -D @stricture/layered
# or
pnpm add -D @stricture/layered
# or
yarn add -D @stricture/layered
```

#### Clean Architecture

```bash
npm install -D @stricture/clean
# or
pnpm add -D @stricture/clean
# or
yarn add -D @stricture/clean
```

#### Next.js

```bash
npm install -D @stricture/nextjs
# or
pnpm add -D @stricture/nextjs
# or
yarn add -D @stricture/nextjs
```

:::tip[Browse All Presets]
See the [Presets](/presets/) page for all available architecture presets.
:::

### Configure ESLint

Add Stricture to your ESLint configuration. You can either use the preset's recommended config (easiest) or configure manually:

<Tabs>
  <TabItem label="Recommended Config (Legacy)">
    ```js
    // .eslintrc.js
    module.exports = {
      extends: ['plugin:@stricture/hexagonal']
    };
    ```

    The preset config automatically enables the `@stricture/enforce-boundaries` rule.
  </TabItem>
  <TabItem label="Manual (Flat Config)">
    ```js
    // eslint.config.js
    import stricture from '@stricture/eslint-plugin';

    export default [
      {
        plugins: {
          '@stricture': stricture
        },
        rules: {
          '@stricture/enforce-boundaries': 'error'
        }
      }
    ];
    ```
  </TabItem>
  <TabItem label="Manual (Legacy .eslintrc.js)">
    ```js
    // .eslintrc.js
    module.exports = {
      plugins: ['@stricture'],
      rules: {
        '@stricture/enforce-boundaries': 'error'
      }
    };
    ```
  </TabItem>
  <TabItem label="Manual (Legacy .eslintrc.json)">
    ```json
    {
      "plugins": ["@stricture"],
      "rules": {
        "@stricture/enforce-boundaries": "error"
      }
    }
    ```
  </TabItem>
</Tabs>

:::tip[Use Preset Configs]
Each preset provides a recommended ESLint config (e.g., `plugin:@stricture/hexagonal`). This is the easiest way to get started with legacy ESLint configs.
:::

## Create Configuration

Create a `.stricture/config.json` file in your project root:

```bash
mkdir -p .stricture
```

For a preset-based setup:

```json title=".stricture/config.json"
{
  "preset": "@stricture/hexagonal"
}
```

Or for a custom configuration:

```json title=".stricture/config.json"
{
  "boundaries": [
    {
      "name": "domain",
      "pattern": "src/domain/**",
      "mode": "file",
      "tags": ["domain"]
    },
    {
      "name": "infrastructure",
      "pattern": "src/infrastructure/**",
      "mode": "file",
      "tags": ["infrastructure"]
    }
  ],
  "rules": [
    {
      "id": "domain-isolation",
      "name": "Domain Isolation",
      "severity": "error",
      "from": { "tag": "domain" },
      "to": { "tag": "infrastructure" },
      "allowed": false,
      "message": "Domain cannot depend on infrastructure"
    }
  ]
}
```

:::note[Configuration Location]
The `.stricture/config.json` file must be in your project root (where `package.json` is located).
:::

## Verify Installation

Run ESLint to verify Stricture is working:

```bash
npx eslint .
```

If you have architecture violations, you'll see errors like:

```
src/domain/user.ts
  5:1  error  Import from 'infrastructure' to 'domain' is not allowed
             Domain cannot depend on infrastructure
             @stricture/enforce-boundaries
```

✅ Stricture is now enforcing your architecture!

## TypeScript Path Aliases (Optional)

If your project uses TypeScript path aliases (like `@/domain`), Stricture will automatically resolve them using your `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/domain/*": ["src/domain/*"],
      "@/infrastructure/*": ["src/infrastructure/*"]
    }
  }
}
```

No additional configuration needed - Stricture reads your `tsconfig.json` automatically.

## IDE Integration

### VS Code

ESLint violations appear inline in VS Code with the [ESLint extension](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint):

1. Install the ESLint extension
2. Restart VS Code
3. Architecture violations appear as red squiggly lines

### WebStorm / IntelliJ

ESLint integration is built-in:

1. Go to **Settings → Languages & Frameworks → JavaScript → Code Quality Tools → ESLint**
2. Enable **Automatic ESLint configuration**
3. Violations appear inline

## Monorepo Setup

For monorepos, you can have per-package configurations:

```
my-monorepo/
├── packages/
│   ├── api/
│   │   ├── .stricture/
│   │   │   └── config.json          # API-specific rules
│   │   └── package.json
│   ├── web/
│   │   ├── .stricture/
│   │   │   └── config.json          # Web-specific rules
│   │   └── package.json
│   └── shared/
│       └── package.json
└── package.json
```

Each package can have its own preset:

```json title="packages/api/.stricture/config.json"
{
  "preset": "@stricture/hexagonal"
}
```

```json title="packages/web/.stricture/config.json"
{
  "preset": "@stricture/nextjs"
}
```

## Troubleshooting

### ESLint not finding violations

**Problem**: ESLint runs but doesn't report Stricture violations.

**Solution**:
1. Verify `.stricture/config.json` exists in project root
2. Check ESLint config has `@stricture/enforce-boundaries` rule enabled
3. Run `npx eslint --debug .` to see what's happening

### TypeScript paths not resolving

**Problem**: Stricture doesn't recognize TypeScript path aliases.

**Solution**:
1. Ensure `tsconfig.json` is in your project root
2. Verify `baseUrl` and `paths` are configured correctly
3. Restart your IDE/ESLint server

### No config file found

**Problem**: Error: `No Stricture config found at .stricture/config.json`

**Solution**:
1. Create `.stricture/config.json` in project root (where `package.json` is)
2. Ensure the file is valid JSON
3. Check file permissions

### Preset not found

**Problem**: Error: `Preset '@stricture/hexagonal' not found`

**Solution**:
1. Install the preset package: `npm install -D @stricture/hexagonal`
2. Verify `package.json` lists the preset in `devDependencies`
3. Run `npm install` again
