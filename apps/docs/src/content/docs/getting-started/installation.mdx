# Installation

Get Stricture running in your TypeScript project in minutes.

## Prerequisites

Before installing Stricture, ensure your project has:

- **Node.js** 18.x or later
- **TypeScript** 4.5 or later
- **ESLint** 8.x or 9.x (flat config supported)
- A TypeScript project with `tsconfig.json`

:::note
Stricture works with both ESLint legacy config (`.eslintrc.*`) and the new flat config (`eslint.config.js`).
:::

## Installation

Install Stricture with your preferred package manager:

<Tabs>
  <TabItem label="npm">
    ```bash
    npm install --save-dev @stricture/core @stricture/eslint-plugin
    ```
  </TabItem>
  <TabItem label="pnpm">
    ```bash
    pnpm add -D @stricture/core @stricture/eslint-plugin
    ```
  </TabItem>
  <TabItem label="yarn">
    ```bash
    yarn add -D @stricture/core @stricture/eslint-plugin
    ```
  </TabItem>
</Tabs>

This installs the core validation engine and the ESLint plugin.

## Configure ESLint

Add Stricture to your ESLint configuration:

<Tabs>
  <TabItem label="Flat Config (ESLint 9+)">
    ```js
    // eslint.config.js
    import stricture from '@stricture/eslint-plugin';

    export default [
      {
        plugins: {
          '@stricture': stricture
        },
        rules: {
          '@stricture/enforce-boundaries': 'error'
        }
      }
    ];
    ```
  </TabItem>
  <TabItem label="Legacy Config (.eslintrc.js)">
    ```js
    // .eslintrc.js
    module.exports = {
      plugins: ['@stricture'],
      rules: {
        '@stricture/enforce-boundaries': 'error'
      }
    };
    ```
  </TabItem>
  <TabItem label="Legacy Config (.eslintrc.json)">
    ```json
    {
      "plugins": ["@stricture"],
      "rules": {
        "@stricture/enforce-boundaries": "error"
      }
    }
    ```
  </TabItem>
</Tabs>

## Create Configuration

Create a `.stricture/config.json` file in your project root:

```bash
mkdir -p .stricture
```

For a preset-based setup:

```json title=".stricture/config.json"
{
  "preset": "@stricture/hexagonal"
}
```

Or for a custom configuration:

```json title=".stricture/config.json"
{
  "boundaries": [
    {
      "name": "domain",
      "pattern": "src/domain/**",
      "mode": "file",
      "tags": ["domain"]
    },
    {
      "name": "infrastructure",
      "pattern": "src/infrastructure/**",
      "mode": "file",
      "tags": ["infrastructure"]
    }
  ],
  "rules": [
    {
      "id": "domain-isolation",
      "name": "Domain Isolation",
      "severity": "error",
      "from": { "tag": "domain" },
      "to": { "tag": "infrastructure" },
      "allowed": false,
      "message": "Domain cannot depend on infrastructure"
    }
  ]
}
```

:::note[Configuration Location]
The `.stricture/config.json` file must be in your project root (where `package.json` is located).
:::

## Verify Installation

Run ESLint to verify Stricture is working:

```bash
npx eslint .
```

If you have architecture violations, you'll see errors like:

```
src/domain/user.ts
  5:1  error  Import from 'infrastructure' to 'domain' is not allowed
             Domain cannot depend on infrastructure
             @stricture/enforce-boundaries
```

✅ Stricture is now enforcing your architecture!

## TypeScript Path Aliases (Optional)

If your project uses TypeScript path aliases (like `@/domain`), Stricture will automatically resolve them using your `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/domain/*": ["src/domain/*"],
      "@/infrastructure/*": ["src/infrastructure/*"]
    }
  }
}
```

No additional configuration needed - Stricture reads your `tsconfig.json` automatically.

## IDE Integration

### VS Code

ESLint violations appear inline in VS Code with the [ESLint extension](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint):

1. Install the ESLint extension
2. Restart VS Code
3. Architecture violations appear as red squiggly lines

### WebStorm / IntelliJ

ESLint integration is built-in:

1. Go to **Settings → Languages & Frameworks → JavaScript → Code Quality Tools → ESLint**
2. Enable **Automatic ESLint configuration**
3. Violations appear inline

## Monorepo Setup

For monorepos, you can have per-package configurations:

```
my-monorepo/
├── packages/
│   ├── api/
│   │   ├── .stricture/
│   │   │   └── config.json          # API-specific rules
│   │   └── package.json
│   ├── web/
│   │   ├── .stricture/
│   │   │   └── config.json          # Web-specific rules
│   │   └── package.json
│   └── shared/
│       └── package.json
└── package.json
```

Each package can have its own preset:

```json title="packages/api/.stricture/config.json"
{
  "preset": "@stricture/hexagonal"
}
```

```json title="packages/web/.stricture/config.json"
{
  "preset": "@stricture/nextjs"
}
```

## Troubleshooting

### ESLint not finding violations

**Problem**: ESLint runs but doesn't report Stricture violations.

**Solution**:
1. Verify `.stricture/config.json` exists in project root
2. Check ESLint config has `@stricture/enforce-boundaries` rule enabled
3. Run `npx eslint --debug .` to see what's happening

### TypeScript paths not resolving

**Problem**: Stricture doesn't recognize TypeScript path aliases.

**Solution**:
1. Ensure `tsconfig.json` is in your project root
2. Verify `baseUrl` and `paths` are configured correctly
3. Restart your IDE/ESLint server

### No config file found

**Problem**: Error: `No Stricture config found at .stricture/config.json`

**Solution**:
1. Create `.stricture/config.json` in project root (where `package.json` is)
2. Ensure the file is valid JSON
3. Check file permissions

### Preset not found

**Problem**: Error: `Preset '@stricture/hexagonal' not found`

**Solution**:
1. Install the preset package: `npm install -D @stricture/hexagonal`
2. Verify `package.json` lists the preset in `devDependencies`
3. Run `npm install` again
