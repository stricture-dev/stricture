# Welcome to Stricture

**Stricture** is an ESLint plugin that enforces architectural boundaries in TypeScript projects. It helps teams maintain clean architecture patterns as codebases scale.

## Why Stricture?

<CardGrid>
  <Card title="Enforce Architecture" icon="puzzle">
    Prevent violations of hexagonal, layered, clean, or modular architecture patterns automatically.
  </Card>
  <Card title="Deny by Default" icon="approve-check">

  </Card>
  <Card title="Clear Violations" icon="information">

## Quick Start

Install Stricture in your project:

```bash
npm install --save-dev @stricture/eslint-plugin
```

Add to your ESLint config:

```js title="eslint.config.js"
import stricture from '@stricture/eslint-plugin'

export default [
  {
    // Your existing ESLint config
    files: ['**/*.ts', '**/*.tsx'],
    plugins: { /* your other plugins */ },
    rules: { /* your other rules */ }
  },
  stricture.configs.hexagonal()  // Add Stricture
]
```

## How It Works

Stricture validates imports between architectural layers:

1. **Define boundaries** - Specify layers like domain, application, infrastructure
2. **Set rules** - Define which layers can import from which
3. **Get violations** - ESLint reports forbidden imports with helpful messages

### Example Violation

```typescript
// ❌ FORBIDDEN: Domain cannot import from infrastructure
// src/domain/user.ts
import { Database } from '../infrastructure/database';  // ❌ ESLint error
```

```
@stricture/enforce-boundaries: Import from 'infrastructure' to 'domain' is not allowed.

Domain layer must remain pure and cannot depend on infrastructure.

To fix this:
- Move database logic to a repository in the infrastructure layer
- Define a port interface in the domain layer
- Inject the repository through the application layer
```

## Key Features

- ✅ **Deny by default** - Only explicitly allowed imports are permitted
- ✅ **Rule specificity** - More specific rules override general ones
- ✅ **Pattern matching** - Use glob patterns for flexible boundary definitions
- ✅ **Helpful errors** - Clear messages with fix suggestions
- ✅ **External dependencies** - Control which layers can import npm packages
- ✅ **Monorepo support** - Per-package configurations
- ✅ **Custom presets** - Create and share your own architecture patterns
- ✅ **CLI tools** - Interactive setup, validation, and scaffolding
